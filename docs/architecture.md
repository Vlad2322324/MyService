# Архитектура

Структура проекта, компоненты и взаимодействие.

## Высокоуровневый обзор

MyService — REST API с трёхслойной архитектурой (handlers → services → repositories).

```
┌─────────────────────────────────────────┐
│ Echo HTTP Server (port 8081)            │
├──────────┬──────────────────────────────┤
│ Middleware:                              │
│ - Request ID (X-Request-ID)            │
│ - Logging (method, path, request_id)   │
├─────────────────────────────────────────┤
│ Handlers (internal/handlers)            │
│ - GetUserById, InsertUser, etc.        │
├─────────────────────────────────────────┤
│ Services (internal/services)            │
│ - Business logic                        │
├─────────────────────────────────────────┤
│ Repositories (internal/repositories)    │
│ - Database access                       │
├─────────────────────────────────────────┤
│ PostgreSQL Database                     │
│ - users table (id, name, created_at)   │
└─────────────────────────────────────────┘
```

## Компоненты

### Entry Point (`cmd/app/main.go`)

1. Загружает конфигурацию из `.env` (godotenv)
2. Инициализирует логгер (zap)
3. Подключается к PostgreSQL
4. Создаёт таблицу `users` (если не существует)
5. Регистрирует middleware (request_id, logging)
6. Регистрирует handlers из OpenAPI
7. Запускает Echo сервер на порту из `$PORT` (default: 8081)
8. Обрабатывает graceful shutdown (SIGINT, SIGTERM)

### Handlers (`internal/handlers/user_handler`)

Реализуют интерфейс, сгенерированный oapi-codegen:

- `GetUserById` — GET /user/{id}
- `InsertUser` — POST /user
- `UpdateUser` — PUT /user/{id}
- `DeleteUser` — DELETE /user/{id}

Каждый handler:
- Валидирует входные данные
- Вызывает сервис
- Логирует ошибки
- Возвращает безопасные HTTP-ответы

### Services (`internal/services/user_service`)

Бизнес-логика:

- `CreateUser(ctx, name)` → создаёт пользователя через репозиторий
- `GetUser(ctx, id)` → получает пользователя
- `UpdateUser(ctx, id, name)` → обновляет пользователя
- `DeleteUser(ctx, id)` → удаляет пользователя (возвращает ошибку если не найден)

### Repositories (`internal/repositories/user_repository`)

Доступ к БД (pgx):

- `NewDatabaseConn(conn *pgx.Conn)` → создаёт репо
- `InitUserTable(ctx)` → создаёт таблицу если нужно
- `InsertUser(ctx, name)` → INSERT + RETURNING
- `GetUserById(ctx, id)` → SELECT by id
- `UpdateUser(ctx, id, name)` → UPDATE by id
- `DeleteUser(ctx, id)` → DELETE by id

SQL запросы используют параметризацию ($1, $2) для безопасности.

### Middleware

**Request ID (`internal/middleware/request_id`):**
- Генерирует или пропускает X-Request-ID
- Сохраняет в контексте запроса
- Используется в логах для трассировки

**Logging (в `main.go`):**
- Логирует каждый запрос (method, path, request_id)
- Использует pkg/logger для структурированного вывода

### Logging (`pkg/logger`)

Обёртка над zap с поддержкой:
- Выбора конфига по `ENV` (production/development)
- Переключения уровня через `LOG_LEVEL` (debug/info/warn/error)
- Глобального `Log *zap.SugaredLogger`

## Data Flow

1. **HTTP запрос** → Echo сервер
2. **Middleware** → Request ID, logging
3. **Handler** → валидация, логирование ошибок
4. **Service** → бизнес-логика
5. **Repository** → SQL запрос к БД
6. **PostgreSQL** → возврат результата
7. **Service** → обработка результата
8. **Handler** → форматирование HTTP ответа
9. **HTTP ответ** → клиенту

## Паттерны кодирования

### Обработка ошибок

```go
if err != nil {
    logger.Log.Errorf("OperationName failed: %v", err)
    return api.Operation500JSONResponse{
        Code:    500,
        Message: "Internal error",
    }, nil
}
```

Ошибка логируется, но клиенту не разглашаются внутренние деталі.

### Валидация входных данных

В handlers проверяются:
- Наличие тела запроса (`request.Body == nil`)
- Обязательные поля (`request.Body.Name == ""`)
- Типы и форматы (Echo + oapi-codegen при необходимости)

### Использование контекста

Все операции с БД получают `context.Context`:
- Timeout protection
- Cancellation support
- Request tracing (request_id)

## CI/CD

GitHub Actions (`.github/workflows/ci.yml`):
1. Checkout код
2. Setup Go 1.23
3. Cache modules
4. Install oapi-codegen
5. Ensure `internal/api/generated` directory exists
6. Run codegen
7. Run `go vet`
8. Run `go test`
9. Run `go build`

При падении любого шага — CI не пройдена.
